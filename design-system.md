# Design System — Vkick

Dark-first design language for the Telegram Mini App + web app.
Concept: **"Floodlit Night"** — a deep green-black pitch under stadium floodlights. The color system
is a strict split: **teal = broadcast** (live state, primary action), **amber = evaluative** (stat
points, crowd ratings). Red is locked to danger, turf green to positive/pitch surfaces. Football
energy without copying FPL's purple.

## 1. Color palette

### Base surfaces (dark-first; light mode is a later phase, not v1)
| Token | Hex | Usage |
|---|---|---|
| `--bg-base` | #081613 | app background (green-black pitch) |
| `--bg-surface` | #0B1D19 | cards, sheets |
| `--bg-elevated` | #122C25 | pinned comments, modals, active rows |
| `--border-subtle` | #1E3B34 | 1px card borders |
| `--text-primary` | #EDF7F3 | headings, scores |
| `--text-secondary` | #93AEA6 | metadata, timestamps |
| `--text-muted` | #7B958C | disabled, placeholders, hints (4.5:1 on every surface) |

### Accents (semantics are strict — one meaning per color across the whole app)
**Teal vs. Amber split:** teal signals broadcast/action, amber signals evaluation. They never mix on
the same UI element.
| Token | Hex | Meaning — and nothing else |
|---|---|---|
| `--volt` | #1FBFA0 | broadcast teal: primary actions, your predictions, CTAs, goal flashes |
| `--live` | #35E0BC | LIVE state only — live dot, live timeline, sub predictor (brighter teal) |
| `--gold` | #F2B705 | evaluative amber: Crowd Ratings, stat points, bonus, Player to Watch |
| `--danger` | #FF4D5E | errors, wrong predictions, red cards |
| `--pitch` | #23A066 | turf green: positive stat chips, Shot Plotter grid (tinted, never dominant) |

Rules:
- Volt (teal) is never a background wash — it's for fills of interactive elements and flashes.
- Points and ratings are always amber, even inside teal-branded contexts (buttons, banners). A
  number that gets evaluated never wears teal; a control that acts never wears amber.
- A team's `color` (from the DB) tints its own fallback badge, tactical discs and stat bars — the only dynamic
  color.
- Accent-on-dark tints (10–20%) for chips/tags: `color-mix(in srgb, var(--volt) 15%, transparent)`.

## 2. Typography

Must support Persian (Vazirmatn) — Iranian audience is v1. Two families, two weights.

| Role | Font | Weights | Usage |
|---|---|---|---|
| Display / numbers | **Archivo** (variable, Google Fonts) | 800–900, expanded width when available | scores, minute numbers, points, countdown |
| UI / body / Persian | **Vazirmatn** | 400, 700 | everything else, full Persian + Latin support |

- Numbers always `font-variant-numeric: tabular-nums` — countdowns and live scores must not jitter.
- Display numerals may use slightly negative letter-spacing in Latin only; Persian text never (breaks joining).
- Scale: display 40/48 (scores), title 20/28, body 16/24, metadata 13/18. Two weights per family, no more.
- Micro-label (panel headings, card meta, table subheads) is one `.label` class in `src/index.css`: 11px/700,
  uppercase with 0.04em tracking in Latin. In Persian that single rule flips case and tracking off and lifts the
  size to 12px, because Vazirmatn below 12px is below the reading floor. Never hand-roll these utilities per site.
- Minute badges ("57'") — Display font, chip with 6px radius, tabular.

## 3. Style & components

- Cards: 14px radius, 1px `--border-subtle`, bg `--bg-surface`, no heavy shadows (elevate with `--bg-elevated` instead).
- Pitch motif: faint pitch-line watermark (center circle / grid lines at 4% opacity) behind prediction cards — brand texture, present but quiet.
- Match card anatomy: competition badge → teams + score (display font) → status chip (SCHEDULED volt outline / LIVE cyan dot pulse / FT gray) → your prediction summary icons.
- Buttons: volt fill, black text, 999px radius for primary; ghost 1px border for secondary.
- **Club identity is the crest.** `TeamBadge` renders the bundled crest (`src/lib/logos.ts`, generated by
  `scripts/import-logos.mjs`) centred in a square footprint at every size (24/36/48px); clubs with no crest fall
  back to their abbreviation on a club-coloured rounded tile in the same square, so a fixture list keeps one rhythm.
  Crests are trimmed and normalized to one artwork size, ship as WebP with a PNG fallback, and are never
  stretched, clipped, or re-coloured. Club colour tints the fallback tile, the tactical discs and the stat bars —
  never a decorative side stripe.
- Icons: one set in `src/components/icons.tsx`, 1.8 stroke on a 24 viewBox, `currentColor`. Glyph characters
  (★ ✕ ▶ ↻ ✓ ⚠) belong to toast text only — `Toast` maps them to this set. Abbreviations that are labels
  ("XI", "VS") stay text; anything pictographic is drawn.
- Touch targets are ≥44px. Where the visual is smaller (the club tile's star and close), the hit area is a 44px
  button around the 20px dot.

## 4. Motion

Durations: `--t-fast` 150ms (hovers, toggles), `--t-std` 250ms (card entrances), `--t-slow` 450ms (celebrations).
Easings: exits/standard `cubic-bezier(0.22,1,0.36,1)`; playful overshoot `cubic-bezier(0.34,1.56,0.64,1)`.
Only transform + opacity animate (60fps). Respect `prefers-reduced-motion`.

### Signature animations
1. **Goal flash** — volt sweep across the match card + 1.2s confetti burst (canvas), score ticks up.
2. **Score odometer** — old digit slides out, new slides in (250ms) on every score change.
3. **Timeline entrance** — events slide in staggered 40ms; live events get a cyan left-edge flash.
4. **Pin drop** (Shot Plotter) — pin falls with overshoot bounce + expanding ripple ring (600ms).
5. **Live dot** — 1.6s double-ring pulse, cyan, infinite while match is live.
6. **Rating snap** — slider snaps to integers with a 10px scale pulse on the number.
7. **Deadline heat** — countdown turns danger red under 60:00, subtle pulse each second in last 10s.
8. **Skeleton shimmer** — 1.4s gradient sweep on loading cards.

## 5. Platform notes

- Telegram Mini App: respect `window.Telegram.WebApp` header color (set to `--bg-base`), haptic feedback on pin drop / rating (`HapticFeedback.impactOccurred('light')`).
- Safe areas + webview viewport quirks; test on low-end Android — keep animations GPU-cheap.
- Web fallback: same tokens, same components; only distribution differs.
