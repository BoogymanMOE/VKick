## What's Working

1. **The front door now obeys rule 1.** On a live matchday the first thing on screen is the live section, and your clubs no longer repeat the fixture that is already showing above them.
2. **The deadline has a body.** A fixed bar in the thumb zone, carrying the pick count, that exists only while a pick can actually be made — it reads the same lock windows the Predict tab does, so it never invites a dead end.

## New finding, fixed during verification

**Boot hung for 32 seconds when telegram.org is unreachable.** `index.html` loaded the Telegram SDK as a synchronous script ahead of the bundle; on a network that blackholes telegram.org — which is Iran, where this app ships — Chrome waits for the TCP timeout before it will even parse the app script. Measured on a fresh tab: `mountedAfterMs: 32211`. The SDK now loads without blocking the parser and settles on load, error, or a 1.5s deadline; `main.tsx` mounts on that signal (with its own 2.5s insurance timer). Re-measured: `mountedAfterMs: 2024`. This was invisible in the build and in the Telegram webview, and it only showed up by actually running the app.

## Priority Issues (remaining)

### [P2] Six screens stand between install and the first fixture
The three-slide intro runs first, then three onboarding steps (favorite → clubs → leagues). The intro is dismissible, which helps, but a first-timer still pays six screens before seeing what is on right now — on the one surface whose whole promise is "open it because a match is on".
**Fix:** lead with the picker and make the three ideas a footer carousel inside it (or drop the intro entirely and teach each mechanic the first time it unlocks, which the hub's progressive tiers already half-do).
**Suggested command:** `$impeccable onboard`

### [P2] The reward screen hides in the settings menu
`/predictions` is the payoff surface: every pick with the resolver's own line items, i.e. the answer to "why did I get 3". Its only entry point is a row inside Profile. The loop is watch → predict → score, and the score step is two taps deep in the wrong tab.
**Fix:** surface it where the points are — a "This matchday" strip on the feed or a link from the Boards header — and keep the Profile row as a secondary path.
**Suggested command:** `$impeccable layout`

### [P3] The tab bar marks "you are here" with colour alone
Active state is volt text plus a 1.8 → 2.2 stroke change and a 1.05 scale. `aria-current` carries it for screen readers, but in grayscale or for a colour-blind user the strip is uniform.
**Fix:** an underline or a pill behind the active icon gives a shape cue that survives greyscale.
**Suggested command:** `$impeccable polish`

### [P3] The boards never lead with your own standing
A viewer below the page limit gets an honest appended row, which is good, but the top of the screen is a list of strangers. The stakes layer needs "your rank and your points" as the first fact, then the board.
**Suggested command:** `$impeccable layout`

## Minor Observations

- The card's stretched link makes the card body non-selectable (`pointer-events-none` on the content wrapper). Correct trade-off for a tappable card, worth knowing if anyone tries to copy a scoreline.
- Cards still show the Predict pill even when every window has closed on a stale-scheduled fixture; the hub tells the truth on arrival, but the feed itself has no window data to filter on.
- `min-h-9` is gone from the hub button; it had never applied (`.min-h-9` is emitted before `.min-h-11` in the built CSS), so nothing visual changed — the intent and the result now agree.
- The sponsored card keeps its "Sponsored" label; the earlier observation that it lacked one was wrong.
