## Anti-Patterns Verdict

**Does this look AI-generated? No.**

**LLM assessment:** The identity is enforced, not decorated: one meaning per colour written into
`tokens.css` as a contract, `.floodlight` / `.pitch-watermark` giving the canvas a sense of place, no
gradients, no glass, no side-stripes, no identical card grid. Contrast is verified rather than assumed
(`--text-muted` clears 4.5:1 at 5.41:1 on `--bg-surface` and 4.62:1 on `--bg-elevated`; `--volt` on
`--bg-base` is 7.49:1). The failure mode is not slop, it is drift: shipped-behaviour claims in comments
that the code does not honour.

**Deterministic scan:** `detect.mjs --json src index.html`, exit **2**, one finding:
- `bounce-easing`, `src/index.css:34` — `cubic-bezier(0.34, 1.56, 0.64, 1)`. Real, not a false positive,
  but partly intentional: PRODUCT.md's "earned spectacle" wants the overshoot on goal/pin moments. The
  problem is scope, not existence.

**Visual overlays:** Browser automation is unavailable in this session, so no overlay was injected and no
`[Human]` tab exists. Fallback signal: source and built-artifact inspection (`dist/assets/index-*.css`),
which is how the `bg-app` finding was proven rather than guessed.

## Overall Impression

A strong product UI with one shipping blocker and three places where the code contradicts its own
comments. The shell, token layer and state machine are better than most shipped sports apps. The things
that feel off are not taste problems.

## What's Working

1. **The colour contract is real.** Teal = broadcast, amber = evaluative, red = danger, turf = pitch —
   and it holds where it is inconvenient, e.g. `StatBar` defaulting to club colour instead of teal.
2. **Three distinct load states.** `Skeleton` / `EmptyState` / `ErrorState` are separate components with
   separate copy, and `Matches.tsx` renders exactly one at a time instead of stacking three empty sections.
3. **Accessibility is engineered, not asserted.** Global `prefers-reduced-motion` collapse, tokenized
   `:focus-visible`, `BottomSheet` traps Tab and restores focus to the invoker, `CollapsibleSection`
   relocates focus out of a panel it is about to unmount.

## Priority Issues

### [P0] The Login screen ships a debug overlay in production

`src/pages/Login.tsx:17-56`, rendered unconditionally at `:138` with no env gate. Restyled in `83b1406`
from a red block to a white bar, which makes it a covering overlay rather than just an ugly one:

```tsx
background: "#ffffff",
color: "#111111",
zIndex: 50,
position: "fixed",
top: 0,
left: 0,
right: 0,
```

**Why it matters:** it is a full-width bar pinned across the top of the viewport on the first screen a new
user sees, covering the `LanguageToggle` header, with no dismiss. It hardcodes `#ffffff` / `#111111` —
colours outside the token layer — and `zIndex: 50` competing with `BottomSheet`'s `z-50`.

**Fix:** delete the component and its import, or gate the render. The diagnostic already exists in
`applyTelegramUrlNormalization`'s `console.log` (`sdkInitData` / `captured` / `changed`):

```tsx
{import.meta.env.DEV ? <TelegramDebugDump /> : null}
```

### [P1] `bg-app` is not a real utility — the sticky day header has no background

`src/pages/Matches.tsx:461`:

```tsx
<div className="sticky top-14 z-10 bg-app/95 backdrop-blur-sm py-1.5">
```

`@theme` in `index.css` defines `--color-base`, `--color-surface`, `--color-elevated`, `--color-ink*`,
`--color-volt/live/gold/danger/pitch`. There is no `app` colour. Proven on the artifact:
`grep -c bg-app dist/assets/index-*.css` -> 0, while `bg-base` -> 10.

**Why it matters:** the "Monday 14 Oct" band renders fully transparent. `backdrop-blur-sm` is all that
stands between it and the cards scrolling underneath, and a blur does not hide text — weekday labels and
team names bleed through the same band. Reads as a rendering glitch.

**Fix:** use the token that exists and drop the blur (`TopBar.tsx` and `TabBar.tsx` both document that the
blur is imperceptible while costing a backdrop read per scroll frame):

```tsx
<div className="sticky top-14 z-10 bg-base/95 py-1.5">
```

Also: `top-14` (56px) is a guess against an actual header height of
`max(env(safe-area-inset-top), 8px) + 44px + 12px` (~64px with no inset), so the band tucks ~8px under
the header. Drive it from a variable.

### [P1] The staggered list entrance is dead code — `--stagger` set 8x, consumed 0x

Set at `MatchCard.tsx:60`, `RatingRow.tsx:35`, `TimelineList.tsx:136`, `Table.tsx:229,322`,
`Leaderboards.tsx:294`, `Login.tsx:158,287`:

```tsx
<li className="list-in" style={{ "--stagger": `${Math.min(index, 8) * 40}ms` } as CSSProperties}>
```

Nothing reads it. `grep -rn "var(--stagger)" src/index.css tokens.css` returns nothing; `.list-in`
(`index.css:484`), `.timeline-in` (`:267`) and `.rise-in` (`:218`) declare `animation` with no
`animation-delay`. `design-system.md:85` and `README.md:237` both document a 40ms stagger as shipped.

**Why it matters:** it is the difference between a list that arrives and a list that fades in as one slab.
The Login cascade the CSS comment promises ("hero, then card, then the legal line") never plays either —
the `70ms` / `140ms` values are inert.

**Fix:**

```css
.list-in,
.timeline-in,
.rise-in {
  animation-delay: var(--stagger, 0ms);
}
```

Keep the existing reduced-motion `animation-delay: 0ms` overrides. Trade-off: with `both` fill a capped
delay leaves the last row invisible for that long, so cap at `Math.min(index, 6) * 30ms`.

### [P1] `AdBanner` is ungated while its kill switch, its gate module and its comment all claim otherwise

`src/components/AdBanner.tsx` renders the A-ADS iframe with no condition, on two screens
(`Matches.tsx:511`, `MatchDetail.tsx:305`). Three artefacts still describe a working switch:

1. `.env.example:61` sets `ADS_ENABLED=false`, with a comment stating both vars "are required for any ad to show".
2. `vite.config.ts:18` defines `__ADS_ENABLED__`; `src/vite-env.d.ts:10` declares the type.
3. `Matches.tsx:221-225` says: *"Renders nothing unless ADS_ENABLED is 'true'; see src/lib/ads.ts."*

But `grep -rn "__ADS_ENABLED__|VITE_ADS_ENABLED" src vite.config.ts` matches only the `define` line — no
reader. And `src/lib/ads.ts` **does not exist** (`ls` fails; the path the comment points at is gone).

**Why it matters:** the ad cannot be turned off, and every signal in the repo says it can. The next person
debugging a bad ad spends an afternoon on `.env` before discovering the flag is inert.

**Fix:** either reinstate the gate in `AdBanner` —

```tsx
const ADS_ENABLED = typeof __ADS_ENABLED__ !== "undefined" && __ADS_ENABLED__ === "true";
export default function AdBanner() {
  if (!ADS_ENABLED) return null;
  ...
```

— or delete `__ADS_ENABLED__` from `vite.config.ts`, `vite-env.d.ts` and `.env.example`, and correct the
`Matches.tsx` comment. Do not leave all three describing a gate that does not exist.

### [P1] The MatchDetail ad sits directly under the fixed pick CTA

`MatchDetail.tsx:305` renders `<AdBanner />` as the last in-flow element, while the pick CTA
(`MatchDetail.tsx:284`) is `fixed inset-x-0 bottom-[calc(56px+max(env(safe-area-inset-bottom),8px))] z-20`.

**Why it matters:** at the bottom of the page the fixed CTA overlaps the ad. `83b1406` fixed the covering
problem on the feed but reintroduced it here, and "partly hidden" is the exact rejection reason A-ADS gave
before. The `Matches.tsx` slot has an explicit comment reasoning about placement; this one does not.

**Fix:** give the CTA the same reserved-space treatment the feed uses (the `h-16` spacer pattern already in
`MatchDetail`), or move the ad above the CTA block so the fixed layer never intersects it.

## Persona Red Flags

**Jordan (first-timer):** the first screen is a white bar of `{"href": "https://..."}` pinned over the
header, with no way to dismiss it. There is no reading of that which is not "this app is broken".

**Sam (keyboard / screen reader):** the shell is strong (skip link, focus ring, trapped Tab, focus
restore). What fails is layering: the debug bar is `z-50`, the same layer as `BottomSheet`, so on the Login
screen a fixed overlay and the sheet layer compete. And the debug `<pre>` is announced before the app's `h1`.

**Casey (one-handed, mobile):** improved by `83b1406` — the tab bar is reachable again, which was the
largest usability failure in the previous tree. Remaining: the language toggle holds the top-right corner
of every header, the least reachable real estate on the device, for a control most users touch once.

## Minor Observations

- `AdBanner` passes `height="auto"` as an HTML attribute, which expects a dimension; the iframe falls back
  to the 150px CSS default while the wrapper declares `min-h-[100px]`. Roughly 50px of the wrapper's
  reserved space does not exist.
- `Matches.tsx:224` "the same node is reused by the two feed states that show it" no longer describes the
  code: there is one render site now.
- `--ease-pop` (the detector's finding) is right on `.pin-drop` / `.goal-flash` where overshoot is the
  point; it reads dated on `.sheet-in` / `.toast-in`. Narrow the token's scope rather than deleting it.
- `--ease-pop` is declared in both `tokens.css` and `index.css`'s `@theme` block. Harmless, but it is the
  kind of duplication that drifts.
- z-index is still eight arbitrary literals with no scale: boot splash `9999`, debug bar `50`, toast
  `z-[60]`, confetti `z-[55]`, sheet + skip link `z-50`, header/tabbar/CTA `z-20`, card link `z-0`.
  The `9999` vs `9999` tie between the boot splash and the removed ad overlay is gone with the overlay,
  but nothing was put in its place.
- `Skeletons.tsx` mirrors the real components' square crest footprint instead of generic bars. That is why
  the loading state does not flash.
