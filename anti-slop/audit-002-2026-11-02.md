## Findings

### R-17 — Data & Numbers (Hard Gate, HIGH)

1. **server/sync/service.ts `syncSeasonFull()` — season window is hardcoded to Aug 2026–May 2027.** The months array is built from literal `2026`/`2027` instead of the current season, so the full-season backfill syncs the wrong (or empty) months once the calendar moves past that window, and silently no-ops the rest of the time. Fix: derive the season start year from `new Date()` (Aug–May) like `currentSeasonLabel()` does, and loop the resulting 10 months.

### R-40 — Performance Mechanisms (Quality Lock, MEDIUM)

2. **server/routes/football.ts — synchronous filesystem probes on the request path.** `localHeadshotUrl()` and `localLogoUrl()` call `existsSync` for every player/team on every list/detail request, and `/api/health/data` calls `readdirSync(FACES_DIR)` plus one `db.prepare` per league per request. These block the Node event loop under load. Fix: cache the face/logo file sets in memory (refresh on a timer or on write) and memoise the health snapshot for ~30s.

### R-38 — Real Content or Honest Placeholder (Quality Lock, MEDIUM)

3. **server/routes/football.ts — mojibake in source comments (`�`).** A find/replace pass left `�` glyphs in at least four comment blocks (lineup/boxscore/h2h/news), corrupting documentation that future edits rely on. Not user-facing, but it is fabricated-looking content in the repo. Fix: restore the original en-dash/hyphen characters (or reword the comments) and save the file as UTF-8.

### R-31 — Every Decision Must Have a Reason (Quality Lock, LOW)

4. **src/lib/formations.ts — undocumented cost constants in `slotCost()`.** The placement heuristic returns magic numbers (0/1/2/3/5/6) and `centrality()` collapses every wide role to `1` with no written rationale, so the slot-affinity behaviour cannot be reviewed or tuned. Fix: add a one-line reason per return value (or extract a small table) and note why wide roles are treated as non-central.

### R-02 — Copywriting (Hard Gate, LOW)

5. **src/pages/TeamPage.tsx — 6 em-dash (`—`) characters remain in source comments.** R-02 forbids the em dash in UI text; these are comments, so not a user-facing violation, but they are the same character audit-001 flagged and should be normalised for consistency. Fix: replace with commas/colons in the affected comments.
